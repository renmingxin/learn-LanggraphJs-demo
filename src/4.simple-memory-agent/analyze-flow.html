6三个容易踩的点

1. 对"内容过短"重试是无效的

SPA 站点返回的 HTML 永远是那 20 多个字符的空壳，重试三次结果完全一样，只多花了两轮等待。重试应只针对网络错误、超时、5xx。

2. 模型返回的不是纯 JSON

经常被 ```json 包裹，或前后带解释。代码用正则先抓数组再 JSON.parse，解析失败会直接抛错，而不是让后面的节点拿到空数组。

3. 正文截断长度要克制

5 个站点 × 1500 字符 ≈ 7.5k 字符进提示词。截到 3000 以上很容易撞上下文上限，也会让汇总变慢、变贵。

7想让抓取更靠谱，三个方向

方向一：只对真故障重试 —— 把 Throw new Error('内容过短') 标记为不可重试，直接返回 ok=false；只对 HTTP 5xx / 超时 / 网络错误 走退避重试。
方向二：换抓取通道 —— 用带渲染的阅读器服务（例如 Jina Reader 这类把页面转成纯文本的接口），SPA 也能拿到正文；代价是多一个外部依赖。
方向三：让模型给可抓取的 URL —— analyzeNode 的提示词里明确要求"给出静态可访问的介绍页/帮助文档页"，而不是营销首页；命中率会明显提升。
