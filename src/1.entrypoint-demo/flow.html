1五个文件各自的职责

每个文件只做一件事：定义工具 → 创建模型 → 调模型 → 调工具 → 编排循环。

定义工具
函数 + zod schema，导出 toolsByName 与 tools
静态数据

创建模型

单例

调模型节点
task('callLLM')：拼 SystemMessage，返回 AIMessage
副作用 · 网络
4.tool-node.ts
调工具节点

控制流

2主循环流程图

蓝紫是模型侧，绿色是工具侧，橙色是判断点。左侧那条回到顶部的路径就是 Agent 的"思考—行动"循环。

入口 模型调用 工具执行 消息拼装 退出

3messages 数组是怎么长出来的

每一轮都在原有历史后面追加消息，模型看到的上下文越来越长。以 200+100-80*100/20 为例。

起点
HumanMessage("200+100-80*100/20") 只有一句话，模型还没有任何工具结果。
第 1 轮
AIMessage：tool_calls = [add, multiply] → ToolMessage(add → 300) ToolMessage(multiply → 8000) 模型先说"我要调这两个"，工具再把结果补齐。顺序必须保持：先 AIMessage，再 ToolMessage。
第 2 轮
AIMessage：tool_calls = [divide] → ToolMessage(divide → 400) 模型发现还差一步除法。
第 3 轮
AIMessage：content = "-100"，tool_calls = [] 没有工具要调了 → break → 这个 AIMessage 就是 agent.invoke() 的返回值。

4最关键的一条规则：AIMessage 必须跟着回去

把 addMessages 那一行写错，整个循环就会断。

错误：只传工具结果
  • 历史里只有一条孤立的 ToolMessage
  • 模型看不到"自己刚才要求调什么"
  • tool_call_id 找不到对应的调用
  • API 直接报错："must be a response to a preceding message"
正确：AIMessage + ToolMessage 一起传
  • addMessages(messages, [modalResponse, ...toolResults])
  • 调用意图（AIMessage）与执行结果（ToolMessage）成对出现
  • 每个 tool_call_id 都能被模型对上号
  • 模型才能基于结果继续推理
