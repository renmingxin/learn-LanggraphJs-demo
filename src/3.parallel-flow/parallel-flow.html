并行流：同一时刻跑三个任务

入口一次扇出（fan-out）到三个节点，三者各自生成内容，再由汇总节点统一收口（fan-in）。对应 3.parallel-flow/agent.ts

1场景与状态

输入一个主题，同时写笑话、故事、诗，最后合并成一份组合输出。

3为什么能并行：耗时对比

假设每次模型调用耗时 t。串行是 3t，并行只有 t（再加汇总的 1 次）。

串行写法（三次 invoke 依次 await）：总耗时约 3t
笑话 · t
故事 · t
诗 · t
并行写法（三条边从 __start__ 同时出发）：总耗时约 t
笑话
故事
诗
三个节点属于同一个"超步"，LangGraph 会一起调度它们，不会互相等待。

4代码与图的对应关系

图上的元素代码说明
三条扇出边addEdge('__start__', 'callLlm1' / 'callLlm2' / 'callLlm3')一条边一条分支，三条边就是三个并行入口
三个创作节点callLlm1 / callLlm2 / callLlm3各自只写自己那个字段：joke / story / poem
三条扇入边addEdge('callLlm1', 'combineLlm') 等三条默认 AND 语义：三条都触发后才执行汇总
汇总节点combineLlm读取三个字段，产出一份组合输出
出口addEdge('combineLlm', '__end__')汇总完成即结束

5运行日志会是交错的

并行执行时，控制台输出不会严格按 1 → 2 → 3 的顺序出现，这是正常的。

[node] callLlm2 开始
[node] callLlm3 开始
[node] callLlm1 开始
[node] callLlm2 完成 → story 已写入
[node] callLlm1 完成 → joke 已写入
[node] callLlm3 完成 → poem 已写入
[node] combineLlm 开始（三个字段齐了）
✔ 返回 state，包含 joke / story / poem / combined

6两个关键规则

1. 并行节点要写不同字段

三个节点写 joke/story/poem，互不冲突。如果两个节点同时写同一个字段，后到的会覆盖先到的（默认 LastValue 通道）。

2. 多条入边默认是"全部到齐才执行"

combineLlm 有 3 条入边，只有当三个上游都完成后它才会跑。这正是"汇合"的实现方式，不需要手动写等待逻辑。

7代码里两个小问题

不影响运行，但建议清理。

重复的边

第 84~87 行把 __start__ → callLlm1 和 __start__ → callLlm2 各写了两遍。LangGraph 内部会去重，所以结果不变，但属于冗余代码，删掉重复的两行即可。

汇总节点的提示词可以更明确

当前提示词只说"写一个组合输出"。如果希望它固定按"笑话 → 故事 → 诗"的结构组织，可以在提示词里明确格式要求，输出会稳定很多。

8想再加一个并行分支

  1. 状态里加一个新字段，例如 quote: Annotation<string>。
  2. 写一个节点 callLlm4，返回 { quote: ... }。
  3. addNode('callLlm4', callLlm4)，并加 addEdge('__start__', 'callLlm4')。
  4. 再加 addEdge('callLlm4', 'combineLlm')，汇总节点就会多等一个分支。
